# 음악 재생 어플 지킴이

선택한 음악 앱의 재생이 멈추면 진동과 알림으로 알려 주는 Android 앱입니다.

멜론과 지니뮤직을 지원하며, 통화·카메라·녹음 중에는 경고를 자동으로 보류할 수 있습니다. 화면을 끈 상태에서도 감시하도록 실행을 유지합니다.

> **현재 버전 0.7.0 · Android 8.0 이상 · 시험용 디버그 서명 APK**


## 주요 기능

- 멜론·지니뮤직 중 감시할 앱 선택 및 중복 선택
- 첫 진동까지 대기 시간·반복 간격·최대 진동 횟수 설정
- 첫 진동부터 빨간 상태 표시와 재생 중단 알림 표시
- 통화·카메라·녹음 감지 시 자동 보류
- 앱과 알림에서 1분·5분·15분 수동 일시정지 및 해제
- 라이트 모드·다크 모드·시스템 설정 따름

**여러 앱을 선택하면 모두 재생 중이어야 정상입니다. 하나라도 재생하지 않으면 경고 대상입니다.**

한 음악 앱의 재생으로 다른 앱이 멈출 수 있습니다. 평소 하나의 앱으로 음악을 듣는다면 **사용하는 앱 하나만 선택**하세요. 이 앱이 두 음악 앱의 동시 재생을 강제하지는 않습니다.

여러 개의 앱으로 동시 재생하는 방법은 https://cafe.naver.com/steamindiegame/21048300 의 사운드 어시스턴트 가이드를 참고하세요.

### 설치 차단과 제한된 설정

APK 설치 차단과 설치 후 ‘알림 접근’ 제한은 서로 다른 단계입니다. GitHub에서 배포해도 시스템의 설치 검사는 적용됩니다. 차단 화면이 나타나면 표시된 사유와 배포 출처를 먼저 확인하세요.

설치는 완료했지만 **알림 접근을 켤 수 없고 ‘제한된 설정’ 안내가 나타나는 경우**, 앱과 배포 출처를 신뢰할 수 있을 때 다음 항목을 확인합니다.

1. 휴대폰 **설정 → 애플리케이션 → 음악 재생 어플 지킴이**로 이동합니다.
2. **더보기(⋮) → 제한된 설정 허용**이 있으면 화면 안내를 따릅니다.
3. 앱으로 돌아와 **① 알림 접근 허용**을 다시 진행합니다.

메뉴 위치와 제공 여부는 Android 버전·제조사·관리 정책에 따라 다릅니다. 이 절차는 설치 자체가 차단된 문제를 해결하는 절차가 아닙니다. [Google의 제한된 설정 안내](https://support.google.com/android/answer/12623953?hl=ko)

## 처음 한 번 설정하기

### 1. 알림 접근 허용 — 필수

앱의 **① 알림 접근 허용**을 누른 뒤 **음악 재생 어플 지킴이 · 재생 상태 접근**을 허용합니다.

선택한 앱의 미디어 재생 상태를 조회하기 위해 필요합니다. 시스템이 부여하는 권한은 전체 알림 접근이지만, 이 앱의 코드는 다른 알림의 내용을 읽거나 저장하지 않습니다.

### 2. 알림 표시 허용 — 필수

앱의 **② 알림 표시 허용**에서 알림을 허용합니다. Android 13 이상에서는 알림 권한 요청이 표시될 수 있습니다.

**알림 접근**은 다른 앱의 재생 상태를 확인하는 권한이고, **알림 표시**는 이 앱이 감시 상태와 경고를 보여 주는 권한입니다. 둘 다 설정해야 감시를 시작할 수 있습니다.

팝업이 필요하면 **재생 중단 팝업 알림 설정**도 확인합니다. 실제 팝업 표시 여부는 시스템의 알림·방해 금지 설정에 따릅니다.

### 3. 배터리 제한 확인 — 화면을 끄고 사용할 때

앱의 **③ 배터리 제한 확인**과 **배터리 최적화 예외 설정**에서 이 앱의 백그라운드 실행이 제한되지 않도록 설정합니다. 기기에 따라 ‘제한 없음’, ‘최적화하지 않음’ 등으로 표시될 수 있습니다.

갤럭시는 추가로 아래 항목을 확인합니다.

1. **설정 → 배터리 → 백그라운드 앱 사용 제한**으로 이동합니다. 일부 버전은 ‘배터리 및 디바이스 케어’ 아래에 있습니다.
2. 이 앱이 **절전 앱·초절전 앱**에 포함되어 있다면 제외합니다.
3. **절전 예외 앱** 또는 **자동 절전 예외 앱** 항목이 있으면 추가합니다.

메뉴 이름은 One UI 버전에 따라 다릅니다. 화면을 끄면 음악 재생 자체가 멈추는 경우에는 음악 앱의 배터리 제한도 확인하세요. [삼성의 백그라운드 앱 설정 안내](https://www.samsung.com/us/support/answer/ANS10003442/)

실행 유지로 배터리 사용량이 늘어납니다. 경고 보류 중에도 상태 확인은 계속됩니다. 사용을 마치면 **감시 종료**를 누르세요.

### 4. 진동과 경고 확인

**진동 테스트**로 진동이 울리는지 확인합니다. 음악 앱을 재생한 뒤 감시를 시작하고, 음악을 멈춰 대기 시간 이후 진동과 알림이 나오는지 확인하세요. 화면을 끈 상태에서도 별도로 확인하는 것이 좋습니다.

## 사용 방법

1. **감시할 앱**에서 앱을 선택하고 **저장**합니다.
2. 바로 아래 **음악 재생 어플 열기**로 음악 앱을 실행하고 재생합니다. 여러 앱을 선택했다면 열 앱을 고릅니다.
3. 진동 시간·최대 횟수와 자동 예외 옵션을 설정합니다.
4. **감시 시작**을 누릅니다.
5. 잠시 쉬려면 **감시 일시정지 / 재개**, 사용을 마치면 **감시 종료**를 누릅니다. 알림에서도 조작할 수 있습니다.

감시 중에는 조용한 실행 알림이 유지됩니다. 재생 중단 경고는 첫 진동부터 표시됩니다.

| 카메라 사용 감지 시 진동 보류 | 켜짐 | 켜기·끄기 |
| 녹음 감지 시 진동 보류 | 꺼짐 | 켜기·끄기 |

진동 시간과 횟수는 입력 후 **진동 설정 저장**을 누릅니다. 자동 예외 옵션은 변경 즉시 저장됩니다.

- 짧게 두 번 울리는 한 묶음이 **1회**입니다. 수동 진동 테스트는 제외합니다.
- 횟수는 감시 시작부터 누적합니다. 재생 재개·보류·설정 변경으로 초기화되지 않습니다.
- 최대 횟수에 도달하면 마지막 진동을 마친 뒤 감시를 종료합니다. 새로 감시를 시작하면 0회부터 셉니다.
- 감시 중 앱 선택이나 시간 설정을 바꾸면 첫 진동 대기 시간을 다시 셉니다.

## 자동 예외와 일시정지

| 보류 사유 | 감지 방식과 범위 |
|---|---|
| 통화 | 기기의 오디오 모드로 판단합니다. 일반 전화·벨 울림·인터넷 통화 등을 포함할 수 있지만, 해당 모드를 사용하지 않는 앱은 감지되지 않을 수 있습니다. |
| 카메라 | 카메라 사용 가능 여부를 확인합니다. 영상 촬영 외에 사진·미리보기·QR 스캔·영상통화나 카메라 사용 불가 상태도 포함될 수 있습니다. |
| 녹음 | 시스템이 제공하는 활성 녹음 상태를 확인합니다. 음성 메모·음성 입력·영상 촬영·인터넷 통화 등이 포함될 수 있으며 모든 녹음을 감지한다고 보장하지 않습니다. |
| 수동 일시정지 | 앱 또는 알림의 ‘일시정지 / 재개’에서 1분·5분·15분을 선택합니다. 남은 시간이 표시되며 일찍 해제할 수 있습니다. |

**적용 중인 모든 보류 사유가 끝나야 경고를 재개합니다.** 수동 보류를 해제해도 자동 예외가 남아 있으면 계속 보류합니다.

보류 중에는 진행 중인 진동과 빨간 경고·재생 중단 알림을 해제하고 횟수를 추가하지 않습니다. 보류가 끝나면 첫 진동 대기 시간을 처음부터 다시 세며 기존 누적 횟수와 최대 제한을 유지합니다. 마지막 허용 진동을 이미 시작했다면 이후 보류가 발생해도 최대 횟수에 도달한 감시는 종료됩니다.

수동 보류 시간을 다시 선택하면 선택 시점부터 새로 셉니다. 수동 보류는 현재 감시 세션에만 적용되며 종료·재부팅 후 유지하지 않습니다.

## 동작 범위와 한계

- 실제 소리나 음량이 아닌 **음악 앱이 보고하는 미디어 재생 상태**를 확인합니다. 실제 청취 가능 여부와 다를 수 있습니다.
- 선택한 앱의 미디어 세션이 없으면 ‘재생 안 함’입니다. 처음부터 정지된 상태로 감시를 시작해도 대기 시간 후 경고합니다.
- 같은 앱에 여러 세션이 있으면 하나라도 재생 중일 때 해당 앱은 재생 중으로 판단합니다.
- 조회 실패나 상태 정보 부족은 ‘확인 불가’로 구분합니다. 다른 선택 앱의 정지가 확인되면 그 정지를 기준으로 경고합니다.
- 알림 접근 연결이 끊기면 경고를 보류하고 권한을 해제하면 감시를 종료합니다.
- 자동 예외 상태를 확인하지 못하면 경고를 보류합니다. 초기 상태 확인에는 잠시 시간이 걸릴 수 있습니다.
- 상태 확인은 약 1초 간격이므로 전환 시 지연이 생길 수 있습니다.
- 재부팅·강제 종료·업데이트 후에는 직접 감시를 다시 시작해야 합니다.
- Android 10 이하의 일부 저메모리 기기에서는 알림 접근 기능을 지원하지 않습니다.

## 개발과 검증

- 최소 Android 8.0(API 26), compileSdk / targetSdk 35
- JDK 17, Android SDK Platform 35, Build Tools 35.0.0
- Gradle Wrapper 8.11.1, Android Gradle Plugin 8.9.2

Android Studio에서 저장소를 열고 SDK 위치를 설정한 뒤 빌드합니다. `local.properties`는 각 개발 환경에서 생성합니다.

```shell
# Windows
gradlew.bat assembleDebug lintDebug

# macOS / Linux
chmod +x gradlew
./gradlew assembleDebug lintDebug
```

APK 출력: `app/build/outputs/apk/debug/app-debug.apk`.

2026-11-10 기준 0.7.0 검증 결과:

- APK 빌드와 서명 검증 통과
- Android 코드 검사 오류 0건, 미사용 문자열 경고 1건
- 타이밍·횟수 제한 69개, 다중 선택 13개, 자동 예외 30개 검사 통과
- 수동 일시정지 테스트 통과

테스트 소스는 `tests/`에 있습니다. 실제 기기의 음악 앱·전화·촬영·녹음 호환성과 장시간 배터리 사용량은 별도 확인이 필요합니다.
